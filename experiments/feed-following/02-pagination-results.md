# 阶段 2 关注流分页验收

2026-11-13 完成。本阶段目标为固定作品集连续翻页全部取到，数量、去重数量、顺序和结束标志均正确。

## 任务完成情况

| 任务 | 实现与结果 |
|---|---|
| 统一排序和游标 | 按 `create_time DESC, id DESC` 排序。服务端生成包含完整时间、字符串 ID 和协议版本的 Base64URL 游标，浏览器原样回传 |
| 后端查询与结束标志 | 按时间和 ID 继续查询，每次读取 `limit + 1` 条，额外一条决定 `has_more`，返回作品数最多为 limit |
| 缓存与前端 | 关注页缓存使用 v3 页面键，包含完整时间、ID、读者、页大小与缓存版本。主页和原 FeedView 调用均使用复合游标，末页停止加载更多 |
| 参数与旧请求兼容 | 损坏、超长、类型错误、不完整的游标，以及刷新携带历史游标、同时传入两种历史边界，均返回 HTTP 400。旧 latest_time 请求继续按秒级严格小于处理，响应保留 next_time，完整分页保证适用于新 cursor 协议 |
| 固定数据与实际入口验收 | 真实 MySQL HTTP 处理器集成测试、当前 Docker 服务 API 和主页自动加载更多验证均通过 |

刷新沿用阶段 1 的请求取消、前端编号校验与服务端缓存版本机制。刷新请求携带空 cursor，成功后替换列表，失败保留原列表和游标。

## 固定数据运行结果

以下每组分别执行未命中缓存、命中缓存、缓存过期和 Redis 不可用四种路径，共 32 个组合。每页 10 条，每页还使用相同游标重复请求，核对返回内容稳定。每组包含未关注作者的干扰作品。

| 固定数据 | 预期条数 | 实收条数 | 去重条数 | 每页数量 |
|---|---:|---:|---:|---|
| 空作品集 | 0 | 0 | 0 | 0 |
| 单条作品 | 1 | 1 | 1 | 1 |
| 恰好一页 | 10 | 10 | 10 | 10 |
| 一页加一条 | 11 | 11 | 11 | 10、1 |
| 多位作者、时间完全相同 | 25 | 25 | 25 | 10、10、5 |
| 同秒、不同毫秒 | 25 | 25 | 25 | 10、10、5 |
| 跨秒与同时间混合 | 100 | 100 | 100 | 十页，每页 10 |
| 同毫秒、不同微秒 | 25 | 25 | 25 | 10、10、5 |

所有组合的 ID 序列均与独立排序的预期序列一致，末页 has_more=false，next_cursor 为空。所有命中缓存组合的作品表查询次数为零。微秒场景在独立临时表的 DATETIME(6) 列上运行，覆盖已有数据库保留更高时间精度的情况。

游标测试还确认了时间与大于 JavaScript 安全整数范围的 ID 在编码解码后保持一致。

## 当前运行服务与浏览器

本地 Docker 服务经 Nginx 和 JWT 鉴权执行另一组 25 条完全同时间作品的检查。

| 页大小 | 每页数量 | 实收 / 去重 | 最后一页 has_more |
|---:|---|---|---|
| 1 | 25 页，每页 1 | 25 / 25 | false |
| 7 | 7、7、7、4 | 25 / 25 | false |
| 10 | 10、10、5 | 25 / 25 | false |
| 50 | 25 | 25 / 25 | false |

主页使用真实测试账号进入关注标签，首次加载 10 条，滚动后自动加载至 20 条、25 条，能够到达最后一条 work 01，并显示“已加载全部关注作品”。到达末尾后继续操作，作品数量保持 25 条。

浏览器验收发现原有远处作品的整块 v-show 会移除占位高度，导致加载 10 条时滚动区域只有约两条作品高度，阻塞加载更多。现改为保留每条作品的 section，仅在当前作品附近渲染播放器。实际滚动已验证修复。

backend 与 frontend 已重建，本地全部 Compose 服务健康。测试结束后已清理 2 个临时账号、25 条作品及相关测试数据和缓存，媒体引用已有文件。

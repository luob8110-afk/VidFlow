## 受控并发与失败测试

后端 `TestFollowingPublicationRefreshPaginationFlow` 使用真实 MySQL、miniredis 和 HTTP 处理器执行以下顺序。

1. 创建 25 条同时间作品并读取旧首页。
2. 暂停已读到旧数据的分页查询。
3. 通过实际发布服务的数据库事务新增一条作品。
4. 注入刷新查询失败，确认返回 HTTP 500。
5. 重试刷新，确认第一条为新作品。
6. 放行旧分页查询，确认后续普通首页仍返回新作品。
7. 用刷新后返回的游标连续翻页，得到 10、10、6 条，核对完整 ID 序列。

前端组合测试执行对应顺序，额外确认失败后保留旧列表和旧游标、显示错误，重试成功后清除错误，迟到分页不能追加到新列表或改写新游标，后续取全 26 条并停止请求。

真实浏览器验证正常组合流程。失败与迟到响应的顺序由上述自动化测试控制。
